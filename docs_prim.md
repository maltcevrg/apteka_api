
# О проекте

## Что делает программа

Это система бонусных карт для сети аптек. У клиента есть карта, на которой хранятся бонусы. Бонусы можно тратить и получать обратно.

## Главные сущности

| Что | Зачем нужно |
|-----|-------------|
| Карта клиента | У каждого клиента своя карта с номером |
| Юридическое лицо | Организация, которой принадлежит аптека |
| Аптека | Торговая точка, где можно потратить бонусы |
| Операция | Запись о том, сколько бонусов прибавили или вычли |
| Баланс | Сколько бонусов осталось на карте |

## Как работает

1. Клиент получает бонусную карту.
2. В аптеке ему начисляют бонусы за покупку.
3. Клиент может потратить бонусы на следующую покупку.
4. Если нужно, операцию можно отменить или вернуть бонусы.
5. Бонусы можно перевести с одной карты на другую.

## Технологии

- **Laravel** — основа сайта и API
- **MySQL** — база данных
- **Passport** — защита API через токены
- **Vue.js** — веб-интерфейс

# Как запустить

## Что нужно

- PHP 8.0 или выше
- Composer
- MySQL
- Node.js (для веб-интерфейса, опционально)

## Шаги

### 1. Скопируйте настройки

```bash
cp .env.example .env
```

Откройте файл `.env` и укажите данные для базы данных:

```
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=apteka
DB_USERNAME=root
DB_PASSWORD=
```

### 2. Установите пакеты PHP

```bash
composer install
```

### 3. Создайте ключ приложения

```bash
php artisan key:generate
```

### 4. Создайте таблицы

```bash
php artisan migrate
```

### 5. Запустите сервер

```bash
php artisan serve
```

Откройте в браузере `http://localhost:8000`.

### 6. Проверьте API

Введите в терминале:

```bash
curl http://localhost:8000/api/v1/check
```

Вы должны увидеть ответ:

```json
{"message": "API работает!"}
```

## Защита API

Чтобы пользоваться остальными адресами API, нужен токен. Получите его через Laravel Passport и передавайте в каждом запросе:

```
Authorization: Bearer ВАШ_ТОКЕН
```

# API — все адреса

Все адреса начинаются с:

```
http://ваш-сайт/api/v1
```

В каждом запросе нужно передавать токен:

```
Authorization: Bearer ВАШ_ТОКЕН
```

### 1. Проверка работы

**GET** `/api/v1/check`

Ответ:

```json
{"message": "API работает!"}
```

### 2. Карты клиентов

#### Посмотреть карту

**GET** `/api/v1/bonus/card/{код_карты}`

Ответ — информация о карте.

#### Создать карту

**POST** `/api/v1/bonus/card`

Нужно передать:

- `short_code` — код карты (от 9 до 13 символов)
- `firstname` — имя
- `name` — фамилия
- `birthdate` — дата рождения
- `gender` — пол (0 — мужской, 1 — женский)
- `newsletter_agree` — согласие на рассылку (0 или 1)
- `status` — статус (0 — активна, 1 — аннулирована, 2 — заменена)

Остальные поля optional: отчество, email, телефон, город, guid.

#### Изменить карту

**PUT** `/api/v1/bonus/card/{код_карты}`

Можно обновить любые поля.

#### Удалить карту

**DELETE** `/api/v1/bonus/card/{код_карты}`

Карта помечается как удалённая.

#### Посмотреть баланс

**GET** `/api/v1/bonus/balance/{код_карты}`

Ответ:

```json
{"balance": 150.50}
```

#### Найти карту по телефону

**POST** `/api/v1/bonus/find`

Нужно передать `phone` в формате `+79001234567`.

### 3. Бонусные операции

#### Начислить бонусы

**POST** `/api/v1/bonus/increase`

Нужно передать:

- `short_code` — код карты
- `pharmacy_number` — номер аптеки
- `inn` — ИНН организации
- `document_date` — дата документа
- `document_number` — номер документа
- `document_type` — тип документа
- `amount` — сумма (больше 0)

#### Вернуть начисление

**POST** `/api/v1/bonus/increase/return`

Те же поля, но сумма отрицательная.

#### Списать бонусы

**POST** `/api/v1/bonus/decrease`

Те же поля, что при начислении. Сумма вычитается.

#### Вернуть списание

**POST** `/api/v1/bonus/decrease/return`

Сумма отрицательная.

#### Отменить операцию

**POST** `/api/v1/bonus/increase/cancel`  
или  
**POST** `/api/v1/bonus/decrease/cancel`

Нужно передать код карты, номер документа, тип документа и дату.

#### Перевести бонусы с карты на карту

**POST** `/api/v1/bonus/move`

Нужно передать:

- `short_code_from` — карта, с которой переводим
- `short_code_to` — карта, на которую переводим
- `document_date` — дата
- `document_number` — номер документа
- `document_type` — тип документа

Весь баланс переводится сразу.

### 4. Аптеки

#### Список аптек

**GET** `/api/v1/bonus/pharmacy`

#### Посмотреть аптеку

**GET** `/api/v1/bonus/pharmacy/{номер}`

#### Создать аптеку

**POST** `/api/v1/bonus/pharmacy`

Нужно передать:

- `legal_entity` — ID юридического лица
- `number` — номер аптеки (от 1 до 99)
- `name` — название

#### Изменить аптеку

**PUT** `/api/v1/bonus/pharmacy/{номер}`

#### Сменить организацию у аптеки

**PUT** `/api/v1/bonus/pharmacy/legal-entity/{номер}`

Нужно передать `legal_entity` — новый ID организации.

#### Удалить аптеку

**DELETE** `/api/v1/bonus/pharmacy/{номер}`

### 5. Юридические лица

#### Список организаций

**GET** `/api/v1/bonus/legal-entity`

#### Посмотреть организацию

**GET** `/api/v1/bonus/legal-entity/{ИНН}`

#### Создать организацию

**POST** `/api/v1/bonus/legal-entity`

Нужно передать:

- `inn` — ИНН (от 10 до 20 цифр)
- `name` — название

#### Изменить организацию

**PUT** `/api/v1/bonus/legal-entity/{ИНН}`

#### Удалить организацию

**DELETE** `/api/v1/bonus/legal-entity/{ИНН}`

### Ответы сервера

| Код | Что означает |
|-----|--------------|
| 200 | Всё хорошо, данные получены или изменены |
| 201 | Что-то создано |
| 202 | Что-то не найдено или не получилось |
| 204 | Удалено успешно |

# База данных

В проекте 5 основных таблиц.

### 1. cards — карты клиентов

| Поле | Что это |
|------|---------|
| short_code | Код карты |
| firstname | Имя |
| name | Фамилия |
| lastname | Отчество |
| birthdate | Дата рождения |
| email | Почта |
| phone | Телефон |
| city | Город |
| gender | Пол (0 — муж, 1 — жен) |
| newsletter_agree | Согласие на рассылку |
| guid | Внешний код |
| status | Статус (0 — активна, 1 — аннулирована, 2 — заменена) |

### 2. legal_entities — юридические лица

| Поле | Что это |
|------|---------|
| inn | ИНН |
| name | Название организации |

### 3. pharmacies — аптеки

| Поле | Что это |
|------|---------|
| number | Номер аптеки |
| name | Название |
| legal_entity_id | Ссылка на организацию |

### 4. card_operations — операции

| Поле | Что это |
|------|---------|
| card_id | Ссылка на карту |
| action | Тип действия (0 — начисление, 1 — списание, 2 — перевод, 3 — возврат начисления, 4 — возврат списания) |
| document_date | Дата документа |
| document_number | Номер документа |
| document_type | Тип документа |
| amount | Сумма |

### 5. bonus_balances — бонусные балансы

| Поле | Что это |
|------|---------|
| card_id | Ссылка на карту |
| legal_entity_id | Ссылка на организацию |
| sum | Сколько бонусов |

### Связи

- У одной карты много операций и балансов.
- У одной организации много аптек и операций.
- У одной аптеки много операций.

# Настройки

Все настройки лежат в файле `.env` в папке с проектом.

## Основное

| Переменная | Что это | Пример |
|------------|---------|--------|
| APP_NAME | Название приложения | Laravel |
| APP_ENV | Среда работы | local |
| APP_DEBUG | Показывать ошибки | true |
| APP_URL | Адрес сайта | http://localhost |

## База данных

| Переменная | Что это |
|------------|---------|
| DB_CONNECTION | Тип базы (mysql) |
| DB_HOST | Адрес сервера базы |
| DB_PORT | Порт (обычно 3306) |
| DB_DATABASE | Имя базы данных |
| DB_USERNAME | Логин |
| DB_PASSWORD | Пароль |

## Почта и очередь

| Переменная | Пример |
|------------|--------|
| MAIL_MAILER | smtp |
| MAIL_HOST | mailhog |
| MAIL_PORT | 1025 |
| QUEUE_CONNECTION | sync |

## Тесты

Для тестов используется отдельный файл `.env.testing`. В нём другая база данных.

Чтобы запустить тесты:

```bash
vendor/bin/phpunit
```

## Важно

Файл `.env` не загружается в репозиторий. Каждый создаёт его сам из `.env.example`.
