# План: отчёты и сверка с 1С

Статус: **план, согласован на уровне требований, код не писался.** Решения заказчика зафиксированы в разделе 1.

## 1. Принятые решения

| Вопрос | Решение |
|---|---|
| Что считать «на дату» | **По дате документа** (`document_date`), не по моменту записи. Опоздавший офлайн-чек попадает в свой день. Отчёт за закрытый период может измениться задним числом — принимаем, закрытие периода не вводим. |
| Дата сторно | Остаётся днём отмены (как сейчас). Отмена ноябрьского чека в декабре — декабрьское движение. |
| Нулевые кошельки в срезе | Показывать. |
| Возвраты (коды 3, 4) | Отдельные колонки, не смешивать с отменами (код 5). |
| Сверка с 1С (п. 3) | Остаётся открытым, см. раздел 4. |
| Отменённые операции в движениях карты | Показывать (исходная + сторно). |
| Отчёт 5 | То же, что отчёт 2, но на произвольную дату / за произвольный период. |
| Форма выдачи | **Excel-файл на скачивание + HTML-страница** в браузере. |
| Доступ | **Отдельный ключ** для отчётов (не касса, не admin-ключ обновления). |
| Сгорание бонусов | Нет. |
| Периоды | Произвольные даты «с — по». |

## 2. Как считается

Единый источник — `card_operations`. Все отчёты — агрегаты по `document_date`, никаких хранимых срезов.

- **Остаток кошелька на дату D** = `SUM(amount)` по строкам карты и юрлица с `document_date ≤ D`.
- **Остаток карты на дату D** = сумма по всем её кошелькам.
- **Начальное сальдо периода** = остаток на день перед началом; **конечное** = остаток на конец периода.
- Поле `card_after`/`wallet_after` в отчётах «на дату» **не используется** (оно по порядку записи, а не по дате документа); оно остаётся для касс и `ledger-check`.

Классификация движений по колонкам:

| Колонка | Строки журнала |
|---|---|
| Начислено | `action = 0`, кроме типа «Ввод остатков» |
| Ввод остатков | `action = 0`, `document_type = 'Ввод остатков'` |
| Возврат начислений | `action = 3` |
| Отменено начислений | `action = 5`, у исходной (`parent_id`) `action ∈ {0, 3}` |
| Списано | `action = 1` |
| Возврат списаний | `action = 4` |
| Отменено списаний | `action = 5`, у исходной `action ∈ {1, 4}` |
| Перенос | `action = 2` (приход и расход отдельно) |
| Частично проведено офлайн | справочно: `amount_requested IS NOT NULL`, разница `amount_requested − amount` |

Все суммы — со знаком, как в журнале; в отчётах колонки «списано/отменено» показываются по модулю, итог сходится: `нач. сальдо + Σ всех движений = кон. сальдо`.

## 3. Отчёты

Все маршруты — `GET /reports/…`, параметры в строке запроса, ключ в заголовке `X-Reports-Key` или параметре `key`. Параметр `format=xlsx` даёт файл, без него — HTML-страница с таблицей и кнопкой «Скачать Excel».

### 3.1. Срез по картам и юрлицам — `/reports/balances`
Параметры: `date` (обязательно), `inn` (необязательно — только одно юрлицо), `nonzero=1` (скрыть нули).
Колонки: `карта; ФИО; ИНН; юрлицо; остаток на дату`. Итог по ИНН и общий. Это отчёт 1.

### 3.2. Обороты по юрлицам — `/reports/legal-entities`
Параметры: `from`, `to` (обязательно).
Колонки по каждому ИНН: `нач. сальдо; начислено; ввод остатков; возврат начислений; отменено начислений; списано; возврат списаний; отменено списаний; перенос +; перенос −; кон. сальдо`. Итоговая строка. Это отчёты 2 и 5 (для «на конец месяца» `from` = 1-е число, `to` = последнее).

### 3.3. Движения карты — `/reports/card`
Параметры: `short_code`, `from`, `to`.
Шапка: карта, ФИО, нач. сальдо (всего и по ИНН). Строки: `дата документа; вид документа; номер; вид движения (словами); ИНН; аптека; сумма; офлайн; запрошено (если частично); отменена (да/нет, дата)`. Подвал: обороты по колонкам из 3.2 и кон. сальдо. Сортировка — по дате документа, затем по `id`. Это отчёт 4.

### 3.4. Сверка с 1С — `/reports/reconcile`
Форма загрузки файла (CSV `карта;остаток`, кодировка cp1251 или UTF-8, разделитель `;`) + `date`. Результат: `карта; остаток 1С; остаток сайта; расхождение`, отдельно «есть только в 1С» и «есть только на сайте», итого расхождений. Каждая строка — ссылка на отчёт 3.3 за период до `date`. Это отчёт 3 в ручном варианте; автоматический разбор — раздел 4.

## 4. Открытое: автоматический разбор расхождений

Чтобы сервер сам объяснял расхождение, ему нужны движения из 1С, а не только остатки. Предлагаемый формат второго файла: `карта;номер документа;тип документа;дата;сумма`. Тогда сверка по каждой карте с расхождением сопоставляет документы по номеру + типу и выдаёт: «есть в 1С, нет на сайте», «есть на сайте, нет в 1С», «разная сумма». Решение зависит от того, может ли 1С сделать такую выгрузку. Пока не решено — делаем 3.4 с ручным разбором через 3.3.

## 5. Технические детали

### 5.1. Excel без composer
На хостинге нет возможности выполнить `composer install`, поэтому библиотеку PhpSpreadsheet не добавляем. Файл `.xlsx` формируется своими силами через стандартное расширение `ZipArchive` (это ZIP с несколькими XML; для таблиц с числами и текстом — ~150 строк кода, без формул и стилей, кроме жирной шапки). Запасной вариант, если `ZipArchive` на хостинге выключен, — CSV с разделителем `;` и BOM, который Excel открывает двойным щелчком.

### 5.2. Доступ
В `.env` — `BONUS_REPORTS_KEY`. Middleware `reports.key` проверяет заголовок/параметр, при ошибке — 403. Ключ отдельный от `BONUS_ADMIN_KEY` (обновление) и от Passport (кассы). Отчёты не пишут в базу — утечка ключа даёт только чтение.

### 5.3. База
Новый индекс `card_operations (document_date, legal_entity_id)` и `(card_id, document_date)` — для агрегатов по датам. Данных не меняем.

### 5.4. Скорость
Отчёт 3.1 на дату — один запрос с `GROUP BY card_id, legal_entity_id`. На сотнях тысяч строк — доли секунды с индексом. Если журнал дорастёт до десятков миллионов строк, добавим кэш отчётов за прошедшие месяцы (таблица результатов, не источник правды). Сейчас не нужно.

### 5.6. Порядок работ
1. Миграция индексов + `ReportService` + тесты расчётов.
2. Middleware, маршруты, HTML-страницы.
3. Писатель xlsx + кнопки скачивания.
4. Сверка (загрузка файла).
5. Документация: docs/03 (раздел «Отчёты»), docs/02 (ключ в `.env`), инструкция бухгалтеру.
