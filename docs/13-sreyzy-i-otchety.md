# Срезы остатков и отчёты

Техническое задание на отчёты и сверку, принятые решения и состояние работ.

## 1. Зачем

API хранит только текущие остатки и журнал операций. Бухгалтерии нужно закрывать месяц (зафиксировать остатки на конец месяца так, чтобы они потом не менялись), видеть обороты по каждому юрлицу, сверять остатки с 1С и разбирать расхождения по картам.

## 2. Термины

- **Срез (свертка)** — зафиксированные остатки на конец месяца. После закрытия месяц не меняется: если потом отменят операцию того месяца, отмена попадёт в месяц, в котором её сделали.
- **Движение** — одна строка журнала `card_operations`: начисление, списание, возврат, перенос.
- **Отмена** — удаление движения (`deleted_at`). Учитывается как отдельное событие в месяце отмены.
- **Сальдо** — остаток. Начальное — на начало периода, конечное — на конец.

## 3. Задачи и статус

| № | Задача | Статус |
|:--|:--|:--|
| 1 | Срез на конец месяца по парам карта + ИНН | **Сделано** (этап 1) |
| 2 | Срез на конец месяца по ИНН: сальдо и обороты | данные есть (сумма строк п. 1), отчёт — этап 2 |
| 3 | Сверка остатков с 1С по картам, отчёт по расхождениям | этап 3 (формат файла 1С пока не определён) |
| 4 | Выписка по карте за период: сальдо и движения | этап 2 |
| 5 | Отчёт по юрлицам за несколько месяцев | этап 2 (то же, что п. 2, за диапазон) |

## 4. Принятые решения

1. **Месяц движения определяется датой документа** (`document_date`), а не датой проведения в API.
2. **Отмена относится к месяцу, в котором её сделали** (`deleted_at`).
3. **Движение или отмена, пришедшие после закрытия своего месяца** (чек задним числом), попадают в первый ещё не закрытый месяц. Закрытый месяц не трогается.
4. **Возвраты — отдельными строками**: «возврат начисления» и «возврат списания» не смешиваются с отменами.
5. **Переносы — отдельной колонкой**, со знаком. С этого этапа перенос пишет по паре операций **на каждое юрлицо**, поэтому срез по ИНН сходится с остатками. Старые переносы без юрлица попадают в строку среза с пустым ИНН.
6. **Месяцы закрываются строго по порядку.** Первый срез строится по всей истории.
7. **Пересчитать можно только последний закрытый месяц и только по секретному ключу** (`BONUS_ADMIN_KEY` в `.env`).
8. Формат файла из 1С для сверки — определить позже.

## 5. Что сделано (этап 1)

### Таблица `balance_snapshots`

Одна строка на месяц × карту × юрлицо.

| Поле | Что значит |
|:--|:--|
| `period` | Первое число месяца |
| `card_id`, `legal_entity_id` | Карта и юрлицо (NULL — старые переносы без юрлица) |
| `opening` | Сальдо на начало месяца = `closing` прошлого среза |
| `increased` | Начислено (action 0) |
| `decreased` | Списано (action 1), положительное число |
| `returned_increase` | Возврат начисления (action 3), положительное |
| `returned_decrease` | Возврат списания (action 4) |
| `moved` | Переносы (action 2), со знаком |
| `cancelled_increase` | Отменено начислений в этом месяце |
| `cancelled_decrease` | Отменено списаний в этом месяце |
| `cancelled_other` | Отменено возвратов/переносов, со знаком исходной суммы |
| `closing` | Сальдо на конец месяца |

Формула: `closing = opening + increased − decreased − returned_increase + returned_decrease + moved − cancelled_increase + cancelled_decrease − cancelled_other`.

Срез по ИНН (задача 2) — это сумма строк за месяц по `legal_entity_id`. Срез по карте без учёта ИНН (для сверки с 1С) — сумма по `card_id`.

В `card_operations` добавлены поля `closed_period` и `cancel_closed_period`: в какой закрытый месяц вошли само движение и его отмена. Пустое поле — ещё не вошло ни в один срез.

### Команда

```bash
php artisan bonus:close-month 2026-10         # закрыть октябрь
php artisan bonus:close-month                 # закрыть предыдущий месяц
php artisan bonus:close-month --recompute --key=СЕКРЕТ   # пересчитать последний закрытый
```

Команда печатает число строк и карт и **проверяет, что срез сходится с текущими остатками** `bonus_balances` (с учётом движений после конца месяца). Если не сходится — выводит таблицу расхождений по картам и завершается с ошибкой; это сигнал, что где-то разошлись журнал и остатки, и нужно разбираться до закрытия.

Автоматически: 1-го числа в 03:00 через планировщик Laravel. Для этого на сервере должна быть строка cron:

```
* * * * * cd /путь/к/проекту && php artisan schedule:run >> /dev/null 2>&1
```

(на виртуальном хостинге, где cron не чаще раза в 5 минут — `*/5 * * * *`, планировщик это переживёт: задача запустится в первый запуск после 03:00).

### Изменение в переносе баланса

`POST /bonus/move` теперь создаёт по две операции на каждое юрлицо, у которого был остаток на карте-источнике (раньше — две операции на перенос целиком, без юрлица). Для касс ничего не меняется; в журнале операций переносов становится больше.

## 6. План дальше

### Этап 2 — отчёты чтения (задачи 2, 4, 5)

Маршруты в группе с токеном, префикс `/api/v1/bonus/report/`:

| Маршрут | Что отдаёт |
|:--|:--|
| `GET report/cards/{ГГГГ-ММ}?inn=` | срез по картам за месяц, фильтр по ИНН, постранично |
| `GET report/legal-entities/{ГГГГ-ММ}` | срез по юрлицам: сальдо и обороты |
| `GET report/legal-entities?from=&to=` | то же за несколько месяцев |
| `GET report/card/{short_code}?from=&to=` | выписка: начальное сальдо, движения (вид документа, номер, дата, вид движения, сумма), конечное сальдо |

Начальное сальдо выписки = ближайший срез до `from` + движения от него до `from`.

Отдельный вопрос — доступ: сейчас один токен на всех. Для отчётов стоит завести отдельного клиента Passport «бухгалтерия» и проверять его на этих маршрутах.

### Этап 3 — сверка с 1С (задача 3)

После того как определён формат выгрузки из 1С: `POST report/reconcile` с файлом и датой → остатки API на дату (срез + движения), свёрнутые по картам → отчёт: карта, остаток 1С, остаток API, разница; результат сохраняется. Разбор расхождения — выписка по карте из этапа 2. Автоматический поиск причины возможен, если 1С выгружает и движения с номерами документов.
