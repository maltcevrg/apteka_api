# API — все адреса

Все адреса начинаются с:

```
http://ваш-сайт/api/v1
```

В каждом запросе нужно передавать токен:

```
Authorization: Bearer ВАШ_ТОКЕН
```

## 1. Проверка работы

**GET** `/api/v1/check`

Ответ:

```json
{"message": "API работает!"}
```

## 2. Карты клиентов

### Посмотреть карту

**GET** `/api/v1/bonus/card/{код_карты}`

Ответ — информация о карте.

### Создать карту

**POST** `/api/v1/bonus/card`

Нужно передать:
- `short_code` — код карты (от 9 до 13 символов)
- `firstname` — имя
- `name` — фамилия
- `birthdate` — дата рождения
- `gender` — пол (0 — мужской, 1 — женский)
- `newsletter_agree` — согласие на рассылку (0 или 1)
- `status` — статус (0 — активна, 1 — аннулирована, 2 — заменена)

Остальные поляoptional: отчество, email, телефон, город, guid.

### Изменить карту

**PUT** `/api/v1/bonus/card/{код_карты}`

Можно обновить любые поля.

### Удалить карту

**DELETE** `/api/v1/bonus/card/{код_карты}`

Карта помечается как удалённая.

### Посмотреть баланс

**GET** `/api/v1/bonus/balance/{код_карты}`

Ответ:

```json
{"balance": 150.50}
```

### Найти карту по телефону

**POST** `/api/v1/bonus/find`

Нужно передать `phone` в формате `+79001234567`.

## 3. Бонусные операции

### Начислить бонусы

**POST** `/api/v1/bonus/increase`

Нужно передать:
- `short_code` — код карты
- `pharmacy_number` — номер аптеки
- `inn` — ИНН организации
- `document_date` — дата документа
- `document_number` — номер документа
- `document_type` — тип документа
- `amount` — сумма (больше 0)
- `offline` — необязательно, `true`/`1`, если чек пробит без связи и отправлен из очереди позже

Ответ `201` — данные операции и поле `balance_after` — баланс карты сразу после операции (можно печатать на чеке, отдельный запрос баланса не нужен):

```json
{"id": 15, "action": 0, "document_date": "2026-07-04", "document_number": "123456789012",
 "document_type": "Чек ККМ", "amount": 100, "amount_requested": null, "offline": false, "balance_after": 250.5}
```

`balance_after` есть в ответах на начисление, списание и оба возврата.

### Баланс может быть отрицательным

Ограничений по остатку нет (с ноября 2026, по новому ТЗ): списание, возврат начисления, отмена и ручная корректировка проводятся **на полную сумму**, даже если на карте не хватает — баланс уходит в минус и восстанавливается следующими начислениями. Ответ `202` на операциях теперь означает только одно: карта не найдена, удалена или аннулирована (`{"message": "Карта не найдена или не действует"}`).

### Повтор запроса (идемпотентность)

Повтор определяется связкой **аптека + номер + тип документа + вид операции + карта**. Если касса не дождалась ответа и прислала ту же операцию ещё раз, сервер **не создаёт вторую**, а возвращает уже записанную с `201` и полем `"duplicate": true`. Один и тот же номер чека в **разных аптеках** — разные документы (нумерация у каждой аптеки своя). Один документ может содержать **много карт** (массовое начисление): каждая карта — отдельная операция с тем же номером документа. Повторная отмена уже отменённого документа возвращает `204` и ничего не меняет. В отмене можно передать `pharmacy_number`, чтобы точно указать аптеку.

### Время документа

Необязательное поле `document_time` (`"10:15"` или `"10:15:30"`) задаёт порядок операций внутри дня. Время можно передать и внутри даты: `"document_date": "20.11.2026 10:15"`. Если время не передано: онлайн-операция получает текущее время сервера, офлайн — считается началом дня (встаёт раньше всех онлайн-операций той же даты).

### Хронология и документы задним числом

Журнал ведётся по **дате и времени документа** (без времени — по порядку поступления). Если чек пришёл задним числом (офлайн-очередь за прошлые дни), он встаёт на своё место по дате, а остатки всех более поздних операций карты пересчитываются автоматически. В ответе на операцию:
- `balance_after` — остаток после **этой** операции в хронологии (для документа задним числом — на его дату);
- `balance` — **текущий** баланс карты после записи. Для показа клиенту на кассе используйте `balance`.

### Офлайн-операции (`offline: true`)

Если касса работала без интернета и отправляет чеки из очереди, в каждом запросе передаётся `offline: true`. На проведение флаг не влияет — он сохраняется в журнале как пометка (видна в админ-панели, фильтр «офлайн»). Поле `amount_requested` в ответе осталось для совместимости и всегда `null` для новых операций (раньше в нём хранилась запрошенная сумма при частичном офлайн-списании).

Если баланс уже 0, запишется строка с `amount: 0`. Так журнал всегда соответствует тому, что касса реально сделала, а баланс никогда не уходит в минус. То же правило действует для офлайн-отмены (`/cancel` с `offline: true`) начисления, которое клиент уже успел потратить.

### Вернуть начисление

**POST** `/api/v1/bonus/increase/return`

Те же поля, но сумма отрицательная.

### Списать бонусы

**POST** `/api/v1/bonus/decrease`

Те же поля, что при начислении. Сумма вычитается.

### Вернуть списание

**POST** `/api/v1/bonus/decrease/return`

Сумма отрицательная.

### Отменить операцию

**POST** `/api/v1/bonus/increase/cancel`  
или  
**POST** `/api/v1/bonus/decrease/cancel`

Нужно передать код карты, номер документа, тип документа и дату. Необязательно — `offline: true` (см. выше).

### Перевести бонусы с карты на карту

**POST** `/api/v1/bonus/move`

Нужно передать:
- `short_code_from` — карта, с которой переводим
- `short_code_to` — карта, на которую переводим
- `document_date` — дата
- `document_number` — номер документа
- `document_type` — тип документа

Весь баланс переводится сразу.

## 4. Аптеки

### Список аптек

**GET** `/api/v1/bonus/pharmacy`

### Посмотреть аптеку

**GET** `/api/v1/bonus/pharmacy/{номер}`

### Создать аптеку

**POST** `/api/v1/bonus/pharmacy`

Нужно передать:
- `legal_entity` — ID юридического лица
- `number` — номер аптеки (от 1 до 99)
- `name` — название

### Изменить аптеку

**PUT** `/api/v1/bonus/pharmacy/{номер}`

### Сменить организацию у аптеки

**PUT** `/api/v1/bonus/pharmacy/legal-entity/{номер}`

Нужно передать `legal_entity` — новый ID организации.

### Удалить аптеку

**DELETE** `/api/v1/bonus/pharmacy/{номер}`

## 5. Юридические лица

### Список организаций

**GET** `/api/v1/bonus/legal-entity`

### Посмотреть организацию

**GET** `/api/v1/bonus/legal-entity/{ИНН}`

### Создать организацию

**POST** `/api/v1/bonus/legal-entity`

Нужно передать:

### Удалить организацию

**DELETE** `/api/v1/bonus/legal-entity/{ИНН}`

## Ответы сервера

| Код | Что означает |
|-----|--------------|
| 200 | Всё хорошо, данные получены или изменены |
| 201 | Что-то создано |
| 202 | Что-то не найдено или не получилось |
| 204 | Удалено успешно |
| 401 | Нет токена или он неправильный |
| 404 | Такого адреса нет |
| 422 | Данные не прошли проверку. В ответе написано, какие поля заполнены неверно |

Ошибки тоже приходят в формате JSON.
